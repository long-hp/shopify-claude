# SF-I18N-01 — Every storefront string goes through `| t`

Requirement and how to verify: `../references/feedback-ledger.md` → `SF-I18N-01`.
Check type: heuristic (hardcoded text) + static (locale key parity)

## Recipe (any theme)

Sweep all `.liquid` (and TS-rendered markup) for literal visible text; route each through `| t`, reusing existing keys first. Add every new key to all locale files, not only the default. Rebuild and compare key parity.

## History

Each entry is one theme where this was fixed. On a theme built on the same base the files
are usually the same paths, so start from the newest entry; if the root cause differs, fix it
from the recipe above and add a new entry.

### Folio — R1 (2026-11-05)

- **Root cause:** Literal English text nodes in `.liquid` (cart drawer, cart page, notices, buttons) and locale files missing keys present in `en`.
- **Fix:** Audit every `.liquid` for literal visible text and replace it with `'<ns>.<path>' | t` (reuse an existing key first: `grep -rin "<text>" src/locales/`). Add new keys to `src/locales/<lang>/NN-<ns>.json` for **every** language, not only `en`. Strings rendered from TS must come from translated data attributes.
- **Files:** `src/locales/*/NN-*.json`, cart drawer/cart page snippets, any snippet with literal text
- **Verify:** `scan-feedback.py --only SF-I18N-01` after `npm run build` (compares built `shopify/locales`); runtime: switch to a non-English locale and walk cart drawer, cart page, PDP, collection, account, 404.
